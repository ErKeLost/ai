# 什么时候需要「治理层」

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| 内部工具、演示、探索型分析 | **轻量通道**（原生文本流） | 简单、体验流畅、几乎零额外成本 |
| 面向客户的对话产品 | 轻量通道 + 收敛组件清单 | 体验优先，失败时安全回退即可 |
| 涉及写操作（下单 / 审批 / 工单） | **治理通道** | 需要授权、防重复提交、审批、回执 |
| 有合规 / 审计要求（金融 / 医疗 / 政企） | **治理通道 + 可回放** | 要能证明「模型没有越权」，每次提交都能查 |
| 需要多端复用（Web / 手机 / 邮件） | 声明式 L2 | 一份意图，多端各自用自己的组件渲染 |

<div class="gu-grid g3" style="margin-top:1rem">
  <div class="gu-card">
    <h4>轻量通道给什么</h4>
    <p>逐字流式、协议原生、成本最低、出 bug 的地方最少。</p>
  </div>
  <div class="gu-card">
    <h4>治理通道给什么</h4>
    <p>编译校验、整体提交/整体拒绝、签名事件、权限绑定、可回放。</p>
  </div>
  <div class="gu-card is-accent">
    <h4>不是二选一</h4>
    <p>同一份组件清单，两条通道并存；按功能选，而不是按产品选。</p>
  </div>
</div>
