## `window.openai` 组件桥接

ChatGPT 提供 `window.openai`，用于兼容性别名和可选的 ChatGPT 扩展。只要共享规范已提供等价能力，新的 UI 就应优先使用 MCP Apps 桥接；`window.openai` 仅用于实现 ChatGPT 特有的功能。

实现步骤详解请参见[构建 ChatGPT UI](https://developers.openai.com/plugins/build/chatgpt-ui)。

如果你的工具需要用户确认，初始 `toolInput` 缺失属于预期行为。在获得批准之前，ChatGPT 不会将需要审批的参数加载到 widget 值中；而是由宿主（host）在用户批准调用后，通过 `ui/notifications/tool-input` 传递这些参数。

### 能力

| 能力 | 作用说明 | 典型用途 |
| --- | --- | --- |
| 状态与数据 | `window.openai.toolInput` | 调用工具时传入的参数。对于需要审批的工具，在宿主于批准后发送 `ui/notifications/tool-input` 之前，该值可能一直为 `null`。 |
| 状态与数据 | `window.openai.toolOutput` | 即你的 `structuredContent`。字段务必保持简洁，因为模型会原样读取这些内容。 |
| 状态与数据 | `window.openai.toolResponseMetadata` | 规范的、仅面向 widget 的工具结果元数据。在 ChatGPT 中包含 `status`、`call_tool_result` 和 `mcp_tool_result`，保留了完整的 MCP 结果信封（envelope），包括隐藏的 `_meta`。 |
| 状态与数据 | `window.openai.widgetState` | 在多次渲染之间持久化的 UI 状态快照。 |
| 状态与数据 | `window.openai.setWidgetState(state)` | 同步保存一份新快照；每次有意义的 UI 交互之后都应调用它。 |
| Widget 运行时 API | `window.openai.callTool(name, args)` | 从 widget 内部调用另一个 MCP 工具（与模型发起的调用方式一致）。 |
| Widget 运行时 API | `window.openai.sendFollowUpMessage({ prompt, scrollToBottom })` | 让 ChatGPT 代为发送一条由组件撰写的消息。`scrollToBottom` 为可选参数，默认为 `true`，可设为 `false` 以阻止自动滚动。 |
| Widget 运行时 API | `window.openai.uploadFile(file, { library?: boolean })` | 上传用户选择的文件并获取一个 `fileId`。传入 `{ library: true }` 可在用户的 ChatGPT 文件库可用时，同时把上传的文件保存到该文件库中。 |
| Widget 运行时 API | `window.openai.selectFiles()` | 打开 ChatGPT 的文件库选择器，并以 `{ fileId, fileName, mimeType }[]` 的形式返回插件有权访问的文件。由于文件库并非对所有用户可用，请对该辅助方法进行特性检测（feature detection）。 |
| Widget 运行时 API | `window.openai.getFileDownloadUrl({ fileId })` | 获取文件的临时下载 URL，适用于由 widget 上传的文件、从文件库中选择的文件、通过文件参数传入的文件，或由工具文件引用（tool file references）返回的文件。 |
| Widget 运行时 API | `window.openai.requestDisplayMode(...)` | 请求画中画（PiP）/全屏模式。 |
| Widget 运行时 API | `window.openai.requestModal({ params, template })` | 创建一个由 ChatGPT 托管的模态框（modal）。省略 `template` 表示沿用当前模板，或传入已注册的模板 URI 来切换模态框内容。 |
| Widget 运行时 API | `window.openai.requestClose()` | 请求 ChatGPT 关闭当前 widget。 |
| Widget 运行时 API | `window.openai.notifyIntrinsicHeight(...)` | 上报 widget 的动态高度，避免内容在滚动时被裁剪。 |
| Widget 运行时 API | `window.openai.openExternal({ href, redirectUrl })` | 在用户的浏览器中打开经过审核的外部链接。对于已获批准的重定向目标，ChatGPT 默认会附加 `?redirectUrl=...`；设为 `redirectUrl: false` 可跳过此步骤。 |
| Widget 运行时 API | `window.openai.setOpenInAppUrl({ href })` | 可选地覆盖全屏模式下显示的外部跳转目标。若未设置，ChatGPT 将保持默认行为，即打开组件当前的 iframe 路径。 |
| 上下文 | `window.openai.theme`、`window.openai.displayMode`、`window.openai.maxHeight`、`window.openai.safeArea`、`window.openai.view`、`window.openai.userAgent`、`window.openai.locale` | 可通过 `useOpenAiGlobal` 读取或订阅的环境信号，用于适配视觉样式与文案。 |

### `useOpenAiGlobal` 辅助函数

许多 ChatGPT UI 项目会将 `window.openai` 的访问封装在一些小的辅助函数中，以便视图保持可测试性。下面这个示例辅助函数会监听宿主的 `openai:set_globals` 事件，让 React 组件能够订阅单个全局值：

```ts
export function useOpenAiGlobal<K extends keyof WebplusGlobals>(
  key: K
): WebplusGlobals[K] {
  return useSyncExternalStore(
    (onChange) => {
      const handleSetGlobal = (event: SetGlobalsEvent) => {
        const value = event.detail.globals[key];
        if (value === undefined) {
          return;
        }

        onChange();
      };

      window.addEventListener(SET_GLOBALS_EVENT_TYPE, handleSetGlobal, {
        passive: true,
      });

      return () => {
        window.removeEventListener(SET_GLOBALS_EVENT_TYPE, handleSetGlobal);
      };
    },
    () => window.openai[key]
  );
}
```

### 关闭 UI

调用 `window.openai.requestClose()` 来请求 ChatGPT 关闭当前 UI。

### 请求其他展示模式

使用 `window.openai.requestDisplayMode` 来请求 inline（内联）、picture-in-picture（画中画）或 fullscreen（全屏）展示：

```tsx
await window.openai?.requestDisplayMode({ mode: "fullscreen" });
// On mobile, picture-in-picture may be presented as fullscreen.
```

### 打开 modal

使用 `window.openai.requestModal` 打开一个由宿主控制的 modal（模态框）。可以提供由同一个 MCP server 注册的另一个 UI 模板的 URI，或者省略 `template` 以打开当前模板：

```tsx
await window.openai.requestModal({
  template: "ui://widget/checkout.html",
});
```

## 文件 API

ChatGPT 以可选的 `window.openai` 扩展形式提供文件上传/下载辅助函数。

| API                                                     | 用途                                              | 说明                                                                                                                                    |
| ------------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `window.openai.uploadFile(file, { library?: boolean })` | 上传用户选择的文件并接收 `fileId`。                  | 传入 `{ library: true }`，在当前用户可以使用文件库（file library）时，将上传的文件同时保存到用户的 ChatGPT 文件库中。                     |
| `window.openai.selectFiles()`                           | 打开文件库选择器以选取已有文件。                     | 返回 `[{ fileId, fileName, mimeType }]`。由于并非所有用户都能使用文件库，需要对该辅助函数做特性检测（feature-detect）。                    |
| `window.openai.getFileDownloadUrl({ fileId })`          | 为文件请求一个临时下载 URL。                         | 适用于由 widget 上传、从文件库中选择、通过 file params 传入，或由 tool file references 返回的文件。                                        |

ChatGPT 文件库是可选功能，并非每个用户都可用。当该辅助函数可用时，从 `window.openai.selectFiles()` 返回的文件已经为当前插件完成授权。可以将返回的 `fileId` 用于 `window.openai.getFileDownloadUrl({ fileId })`，或在使用 file params 的工具输入中。

上传用户选择的文件：

```tsx
const { fileId } = await window.openai.uploadFile(file, {
  library: true,
});
```

选择用户已上传到 ChatGPT 的文件：

```tsx
if (window.openai?.selectFiles) {
  const files = await window.openai.selectFiles();
  // [{ fileId, fileName, mimeType }]
}
```

请对 `window.openai.selectFiles` 做特性检测，当文件库不可用时回退到 `window.openai.uploadFile`。

请求临时下载 URL：

```tsx
const { downloadUrl } = await window.openai.getFileDownloadUrl({ fileId });
```

### 定义文件输入

要让 ChatGPT 向工具传递文件，需在 `_meta["openai/fileParams"]` 中列出每个顶层文件输入。所列出的每个字段必须解析为一个文件对象或文件对象数组。

每个文件对象的 schema 都必须声明全部四个受支持的属性：

| 属性           | 类型     | 在 `properties` 中声明 | 包含在 `required` 中 |
| -------------- | -------- | :--------------------: | :------------------: |
| `download_url` | `string` |           是           |          是          |
| `file_id`      | `string` |           是           |          是          |
| `mime_type`    | `string` |           是           |          否          |
| `file_name`    | `string` |           是           |          否          |

`mime_type` 和 `file_name` 是可选值，但你必须在 schema 中声明它们的属性。**Scan Tools** 步骤和插件提交流程会拒绝以下文件 schema：遗漏了四个属性中的任何一个、未将 `download_url` 和 `file_id` 设为必填、将任一可选属性标记为必填，或将 `download_url` 和 `file_id` 之外的属性设为必填。你可以声明额外的可选属性。

下面这个完整的 tool descriptor（工具描述符）接受一个必填的文件输入：

```json
{
  "name": "analyze_file",
  "title": "Analyze file",
  "description": "Analyzes a user-provided file without modifying it.",
  "inputSchema": {
    "type": "object",
    "$defs": {
      "OpenAIFile": {
        "type": "object",
        "properties": {
          "download_url": { "type": "string" },
          "file_id": { "type": "string" },
          "mime_type": { "type": "string" },
          "file_name": { "type": "string" }
        },
        "required": ["download_url", "file_id"],
        "additionalProperties": false
      }
    },
    "properties": {
      "file": { "$ref": "#/$defs/OpenAIFile" }
    },
    "required": ["file"]
  },
  "annotations": {
    "readOnlyHint": true,
    "openWorldHint": false,
    "destructiveHint": false
  },
  "_meta": {
    "openai/fileParams": ["file"]
  }
}
```

要接受多个文件，可将顶层字段定义为数组，并在 `items` 中使用相同的文件对象 schema。工具可以独立于每个文件对象内部所要求的属性，单独要求顶层的文件字段。

在运行时，ChatGPT 使用 snake case（蛇形命名）字段传递文件值：

```json
{
  "download_url": "https://...",
  "file_id": "file_...",
  "mime_type": "image/png",
  "file_name": "input.png"
}
```

ChatGPT 总是会包含 `download_url` 和 `file_id`；`mime_type` 和 `file_name` 则可能被省略。当 widget 需要获取新的临时下载 URL 时，可将 `file_id` 用作 `window.openai.getFileDownloadUrl({ fileId })` 的 `fileId` 值。

在持久化 widget 状态时，如果希望模型在后续对话轮次中能看到 image ID，请使用结构化形式（`modelContent`、`privateContent`、`imageIds`）。

## 工具描述符参数

默认情况下，工具描述（tool description）应包含[此处](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#tool)列出的字段。

任何返回 `structuredContent` 的工具都应声明 `outputSchema`。该 schema 应准确描述工具返回的对象，以便客户端能够校验结果，模型也能据此推理后续的工具调用。

### 工具描述符上的 `_meta` 字段

在工具描述符上使用以下 `_meta` 字段。将工具关联到 UI 模板时，优先使用 MCP Apps 标准键 `_meta.ui.resourceUri`。出于兼容性和可选扩展的考虑，ChatGPT 还支持 OpenAI 特有的元数据。

| 键                                        |       位置       | 类型         | 限制                                            | 用途 |
| ----------------------------------------- | :-------------: | ------------ | ----------------------------------------------- | ---- |
| `_meta["securitySchemes"]`                | 工具描述符 | array        | 无                                            | 为仅读取 `_meta` 的客户端提供的向后兼容镜像。 |
| `_meta.ui.resourceUri`                    | 工具描述符 | string (URI) | 无                                            | UI 模板的标准资源 URI。 |
| `_meta.ui.visibility`                     | 工具描述符 | string[]     | 默认 `["model", "app"]`                      | 控制工具可供模型、UI 还是两者使用。`app` 值是 MCP Apps 协议中 UI 的标识符。 |
| `_meta["openai/outputTemplate"]`          | 工具描述符 | string (URI) | 无                                            | ChatGPT 中 `_meta.ui.resourceUri` 的 OpenAI 特有可选/兼容别名。 |
| `_meta["openai/profile"]`                 | 工具描述符 | boolean      | 可选；仅 `true` 表示 profile 工具 | 标识经过身份验证、返回当前用户资料的只读工具。实现它可以帮助用户识别和管理多个已连接的账户。没有它，用户同样可以连接多个账户。参见[支持多个账户](https://developers.openai.com/plugins/build/auth#support-multiple-accounts)。 |
| `_meta["openai/widgetAccessible"]`        | 工具描述符 | boolean      | 默认 `false`                                 | 现有 UI 集成所使用的 OpenAI 特有兼容字段；建议改用 `_meta.ui.visibility` + `tools/call`。 |
| `_meta["openai/visibility"]`              | 工具描述符 | string       | `public`（默认）或 `private`                 | 现有 UI 集成所使用的 OpenAI 特有兼容字段；建议改用 `_meta.ui.visibility`。 |
| `_meta["openai/toolInvocation/invoking"]` | 工具描述符 | string       | ≤ 64 个字符                                      | 工具运行期间显示的简短状态文本。 |
| `_meta["openai/toolInvocation/invoked"]`  | 工具描述符 | string       | ≤ 64 个字符                                      | 工具完成后显示的简短状态文本。 |
| `_meta["openai/fileParams"]`              | 工具描述符 | string[]     | 无                                            | 表示文件的顶层输入字段列表。每个字段会收到 `{ download_url, file_id, mime_type?, file_name? }`。 |

示例：

```ts



registerAppTool(
  server,
  "search",
  {
    title: "Public Search",
    description: "Search public documents.",
    inputSchema: { q: z.string() },
    outputSchema: {
      results: z.array(
        z.object({
          id: z.string(),
          title: z.string(),
          url: z.string(),
        })
      ),
    },
    securitySchemes: [
      { type: "noauth" },
      { type: "oauth2", scopes: ["search.read"] },
    ],
    _meta: {
      securitySchemes: [
        { type: "noauth" },
        { type: "oauth2", scopes: ["search.read"] },
      ],
      ui: { resourceUri: "ui://widget/story.html" },
      // Optional compatibility alias (ChatGPT only):
      // "openai/outputTemplate": "ui://widget/story.html",
      "openai/toolInvocation/invoking": "Searching…",
      "openai/toolInvocation/invoked": "Results ready",
    },
  },
  async ({ q }) => {
    const results = await performSearch(q);

    return {
      structuredContent: { results },
      content: [{ type: "text", text: `Found ${results.length} results.` }],
    };
  }
);
```

### 注解（Annotations）

要将工具标记为“只读”，请在工具描述符（tool descriptor）上使用以下
[`ToolAnnotations`
字段](https://modelcontextprotocol.io/specification/2025-11-25/schema#toolannotations)：

| 键                | 类型    | 是否必需 | 说明                                                                                                                                                                                                                                        |
| ----------------- | ------- | :------: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `readOnlyHint`    | boolean | 必需     | 表明该工具仅用于检索或计算信息，不会在对话之外创建、更新、删除或发送数据。                                                                                                                                                                  |
| `destructiveHint` | boolean | 必需     | 声明该工具可能会删除或覆盖用户数据，以便宿主（host）知道需要先征得用户的明确批准。                                                                                                                                                          |
| `openWorldHint`   | boolean | 必需     | 声明该工具会访问公共互联网或开放式外部实体，包括通过网络搜索等只读操作进行访问。有边界的私有账户或工作区，并不会仅仅因为托管在外部就属于 open-world。                                                                                        |
| `idempotentHint`  | boolean | 可选     | 声明使用相同参数调用该工具不会对其环境产生额外影响。                                                                                                                                                                                        |

这些提示只会影响 ChatGPT 或 Codex 向用户呈现工具调用的方式；服务端仍须自行实现并执行各自的授权逻辑。

示例：

```ts


server.registerTool(
  "list_saved_recipes",
  {
    title: "List saved recipes",
    description: "Returns the user’s saved recipes without modifying them.",
    inputSchema: {},
    outputSchema: {
      recipes: z.array(
        z.object({
          id: z.string(),
          title: z.string(),
        })
      ),
    },
    annotations: { readOnlyHint: true },
  },
  async () => ({
    structuredContent: { recipes: await fetchSavedRecipes() },
  })
);
```




## 组件资源 `_meta` 字段

请在承载组件的资源模板（通过 `registerResource` 注册）上设置这些键。它们帮助 ChatGPT 描述并组织所渲染的 iframe，同时不会将元数据泄露给其他客户端。

| 键                                         |       位置        | 类型            | 用途                                                                                                                                                                                              |
| ------------------------------------------ | :---------------: | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `_meta.ui.prefersBorder`                   | 资源内容（Resource contents） | boolean         | 提示在支持的情况下，组件应渲染在带边框的卡片内。                                                                                                                                                  |
| `_meta.ui.csp`                             | 资源内容（Resource contents） | object          | 标准 widget CSP 字段的首选元数据载体：`connectDomains`、`resourceDomains`，以及可选的 `frameDomains`。                                                                                             |
| `_meta.ui.domain`                          | 资源内容（Resource contents） | string (origin) | 托管组件的专用 origin（提交带 UI 的插件时必需；每个插件必须唯一）。默认值为 `https://web-sandbox.oaiusercontent.com`。                                                                             |
| `_meta["openai/ui"].availableDisplayModes` | 资源内容（Resource contents） | string[]        | 支持的显示模式：`inline`、`fullscreen` 和 `pip`。让 ChatGPT 在加载组件之前即可选择显示模式。                                                                                                       |
| `_meta["openai/widgetDescription"]`        | 资源内容（Resource contents） | string          | 组件加载时呈现给模型的人类可读摘要，可减少助手多余的复述。                                                                                                                                        |
| `_meta["openai/widgetPrefersBorder"]`      | 资源内容（Resource contents） | boolean         | ChatGPT 中 `_meta.ui.prefersBorder` 的 OpenAI 专用兼容别名。                                                                                                                                      |
| `_meta["openai/widgetCSP"]`                | 资源内容（Resource contents） | object          | 旧的 ChatGPT 兼容键，用于 widget CSP 元数据。标准 CSP 字段已被 `_meta.ui.csp` 取代，但对于受信任的 `openExternal` 目标地址，`redirect_domains` 仍然是必需的。                                      |
| `_meta["openai/widgetDomain"]`             | 资源内容（Resource contents） | string (origin) | ChatGPT 中 `_meta.ui.domain` 的 OpenAI 专用兼容别名。                                                                                                                                             |

ChatGPT 支持旧的 `_meta["openai/widgetCSP"]` 兼容键，其字段采用以下 snake_case 命名：

- `connect_domains`: `string[]`
- `resource_domains`: `string[]`
- `frame_domains?`: `string[]`
- `redirect_domains?`: `string[]`。ChatGPT 针对 `window.openai.openExternal` 重定向目标的扩展字段。

对于新 UI，通常更推荐使用标准的 `_meta.ui.csp` 对象，它支持：

- `connectDomains`: `string[]`。widget 可通过 fetch/XHR 访问的域名。
- `resourceDomains`: `string[]`。静态资源（图片、字体、脚本、样式）所在的域名。
- `frameDomains?`: `string[]`。允许用于 iframe 嵌入的 origin 可选列表。默认情况下，widget 无法渲染子框架（subframe）。插件可以在 [iframe 政策](https://developers.openai.com/plugins/plugin-guidelines#iframes-and-embedded-pages)允许的范围内嵌入自己的域名，包括现有的编辑器和管理界面。提交时需要提供理由说明，且使用 iframe 可能需要额外审核，或导致审批速度变慢。

不过，`_meta.ui.csp` 并不支持为 `window.openai.openExternal(...)` 链接配置 `redirect_domains`。若要将重定向目标加入允许列表，仍必须设置 `_meta["openai/widgetCSP"].redirect_domains`。

### 在 UI 加载之前声明显示模式

在服务器返回的资源内容上设置 `_meta["openai/ui"].availableDisplayModes`。对于仅支持全屏（fullscreen）的组件，这能让 ChatGPT 立即以全屏方式打开它，而无需先显示内联（inline）加载状态。

在该资源的 `contents` 数组中返回这个对象，并将 `html` 设置为组件的 HTML：

```ts
const resource = {
  uri: "ui://widget/viewer.html",
  mimeType: "text/html;profile=mcp-app",
  text: html,
  _meta: {
    "openai/ui": {
      availableDisplayModes: ["fullscreen"],
    },
  },
};
```

请列出组件支持的所有模式，例如 `["inline", "fullscreen"]`。在 MCP Apps 初始化流程中也要继续声明 `availableDisplayModes`；服务器端的声明是对该流程的补充，后者还支持动态显示模式。

## 工具结果

工具结果可以包含以下[字段](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#tool-result)。值得注意的有：

| 键                  | 类型                  | 是否必填 | 说明                                                                                             |
| ------------------- | --------------------- | -------- | ------------------------------------------------------------------------------------------------ |
| `structuredContent` | object                | 可选     | 提供给模型和组件。如果声明了 `outputSchema`，则必须与之匹配。                                     |
| `content`           | string 或 `Content[]` | 可选     | 提供给模型和组件。                                                                               |
| `_meta`             | object                | 可选     | 仅传递给组件，对模型隐藏。                                                                       |

只有 `structuredContent` 和 `content` 会出现在对话记录中。宿主（host）会将 `_meta` 转发给组件，因此你可以在不向模型暴露数据的情况下为 UI 提供数据。

宿主提供的工具结果元数据：

| 键                                |               位置               | 类型   | 用途                                                                                       |
| --------------------------------- | :------------------------------: | ------ | ------------------------------------------------------------------------------------------ |
| `_meta["openai/widgetSessionId"]` | 工具结果 `_meta`（来自宿主）      | string | 当前已挂载 widget 实例的稳定 ID；可用于关联日志和工具调用，直至该 widget 卸载。              |

示例：

```ts



registerAppTool(
  server,
  "get_zoo_animals",
  {
    title: "get_zoo_animals",
    inputSchema: { count: z.number().int().min(1).max(20).optional() },
    outputSchema: {
      animals: z.array(
        z.object({
          id: z.string(),
          name: z.string(),
          species: z.string(),
        })
      ),
    },
    _meta: { ui: { resourceUri: "ui://widget/widget.html" } },
  },
  async ({ count = 10 }) => {
    const animals = generateZooAnimals(count);

    return {
      structuredContent: { animals },
      content: [{ type: "text", text: `Here are ${animals.length} animals.` }],
      _meta: {
        allAnimalsById: Object.fromEntries(
          animals.map((animal) => [animal.id, animal])
        ),
      },
    };
  }
);
```

### 错误工具结果

要在工具结果中返回错误，请使用以下 `_meta` 键：

| 键                              | 用途     | 类型               | 说明                                                       |
| ------------------------------- | -------- | ------------------ | ---------------------------------------------------------- |
| `_meta["mcp/www_authenticate"]` | 错误结果 | string 或 string[] | 用于触发 OAuth 的 RFC 7235 `WWW-Authenticate` 质询（challenge）。 |

## 客户端提供的 `_meta` 字段

| 键                             | 提供时机                | 类型             | 用途                                                                                          |
| ------------------------------ | ----------------------- | ---------------- | ---------------------------------------------------------------------------------------------- |
| `_meta["openai/locale"]`       | Initialize + 工具调用   | string (BCP 47)  | 请求的区域设置（较旧的客户端可能发送 `_meta["webplus/i18n"]`）。                                |
| `_meta["openai/userAgent"]`    | 工具调用                | string           | 可选的、尽力而为的用户代理提示，用于分析或格式化。                                              |
| `_meta["openai/userLocation"]` | 工具调用                | object           | 粗粒度的位置提示（`city`、`region`、`country`、`timezone`、`longitude`、`latitude`）。          |
| `_meta["openai/subject"]`      | 工具调用                | string           | 发送给 MCP 服务器的匿名化用户 ID，用于限流和身份识别。                                          |
| `_meta["openai/session"]`      | 工具调用                | string           | 匿名化的会话 ID，用于关联同一 ChatGPT 会话内的工具调用。                                        |
| `_meta["openai/organization"]` | 工具调用                | string           | 与当前 ChatGPT 组织关联的匿名化组织 ID（在可用时提供）。                                        |

操作阶段的 `_meta["openai/userAgent"]` 和 `_meta["openai/userLocation"]` 仅仅是提示信息；服务器绝不应依赖它们做授权决策，并且必须能够容忍它们缺失的情况。请将 `_meta["openai/userAgent"]` 视为可选的、尽力而为的元数据，而不是用于检测是哪个宿主界面在调用你的服务器的可靠手段。

示例：

```ts


server.registerTool(
  "recommend_cafe",
  {
    title: "Recommend a cafe",
    inputSchema: {},
    outputSchema: {
      cafes: z.array(
        z.object({
          name: z.string(),
          address: z.string(),
        })
      ),
    },
  },
  async (_args, { _meta }) => {
    const locale = _meta?.["openai/locale"] ?? "en";
    const location = _meta?.["openai/userLocation"]?.city;
    const cafes = await findNearbyCafes(location);

    return {
      content: [{ type: "text", text: formatIntro(locale, location) }],
      structuredContent: { cafes },
    };
  }
);
```
