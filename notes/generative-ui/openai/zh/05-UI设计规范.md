# UI 指南

> 完整的文档索引请参见 [llms.txt](/llms.txt)。在页面 URL 末尾追加 `.md` 即可获取对应文档页面的 Markdown 版本。

## 概述

可选的插件 UI 能够扩展用户的能力，同时不打断对话流程。只有当视觉交互能改善工作流程时，才应使用卡片、轮播、全屏视图等显示模式。

![ChatGPT 移动端界面中的应用示例](https://developers.openai.com/images/apps-sdk/overview.png)

## 设计系统

要设计出与 ChatGPT 原生体验一致的高质量 UI，可以使用 [`@openai/apps-sdk-ui`](https://openai.github.io/apps-sdk-ui/) 组件库。

它提供基于 Tailwind 的样式基础、CSS 变量形式的设计令牌（design tokens），以及一套精心打磨、无障碍友好的组件。

该组件库是可选的。它提供了一条更快的途径，帮你构建符合 ChatGPT 设计系统的组件。

在深入编写代码之前，可以先使用我们的 [Figma 组件库](https://www.figma.com/community/file/1625636989296445101) 开始设计。

## 显示模式

显示模式是开发者在 ChatGPT 中为应用构建体验时所依托的界面载体。它们让合作伙伴能够展示与对话自然融合的内容和操作。每种模式都针对特定类型的交互而设计，从快速确认到沉浸式工作流。

一致地运用这些模式，有助于让体验保持简洁且可预期。

### 内联（Inline）

内联显示模式直接出现在对话流中。内联界面目前始终出现在模型生成的回复之前。每个应用最初都会以内联形式呈现。

![ChatGPT 中的内联卡片与轮播示例](https://developers.openai.com/images/apps-sdk/inline_display_mode.png)

**布局**

- **图标与工具调用（Icon & tool call）**：显示应用名称和图标的标签。
- **内联展示（Inline display）**：一种轻量级展示方式，将应用内容嵌入在模型回复上方。
- **后续回复（Follow-up）**：在组件之后显示的一段由模型生成的简短回复，用于建议修改、后续步骤或相关操作。避免与卡片内容重复。

#### 内联卡片（Inline card）

轻量级、用途单一的组件，直接嵌入对话之中，用于提供快速确认、基础操作或视觉辅助。

**适用场景**

- 单一操作或决策（例如，确认预订）。
- 少量结构化数据（例如，地图、订单摘要或快速状态）。
- 完全自包含的组件或工具（例如，音频播放器或记分卡）。

**布局**

![内联卡片示意图](https://developers.openai.com/images/apps-sdk/inline_card_layout.png)

- **标题（Title）**：如果卡片基于文档（document-based），或包含带有父级元素的项目（例如播放列表中的歌曲），则应包含标题。
- **展开（Expand）**：当卡片包含富媒体或交互性内容（如地图或交互式图表）时，用于打开全屏显示模式。
- **显示更多（Show more）**：当多个结果以列表形式呈现时，用于展示更多项目。
- **编辑控件（Edit controls）**：在不干扰对话的前提下，为应用响应提供内联编辑支持。
- **主要操作（Primary actions）**：最多限制为两个操作，放置在卡片底部。操作应触发一轮对话（conversation turn）或一次工具调用（tool call）。

**交互**

![内联卡片交互模式示意图](https://developers.openai.com/images/apps-sdk/inline_card_interaction.png)

卡片支持基本的直接交互。

- **状态（States）**：用户所做的编辑会被持久保存。
- **基本直接编辑（Basic direct edits）**：在合适的情况下，提供内联可编辑文本，让用户无需提示模型即可快速完成修改。
- **动态布局（Dynamic layout）**：卡片布局的高度可随内容自动扩展，上限为移动端显示区域的高度。

**经验法则**

- **限制每张卡片的主要操作数量**：最多支持两个操作，包括一个主要 CTA 和一个可选的次要 CTA。
- **卡片内不做深层导航或多视图。**卡片中不应包含多级下钻（drill-in）、标签页或更深的导航层级。建议将这些内容拆分为独立的卡片或工具操作。
- **禁止嵌套滚动。**卡片应自动适配内容大小，避免出现内部滚动。
- **禁止重复输入。**不要在卡片中复刻 ChatGPT 已有的功能。

![内联卡片中应避免的模式示例](https://developers.openai.com/images/apps-sdk/inline_card_rules.png)

#### 内联轮播（Inline carousel）

一组并排呈现的卡片，让用户能够快速浏览并从多个选项中做出选择。

**适用场景**

- 展示少量同类项目（例如餐厅、播放列表、活动）。
- 项目的视觉内容和元数据较多，无法在基本列表行中完整呈现。

**布局**

![内联轮播示意图](https://developers.openai.com/images/apps-sdk/inline_carousel_layout.png)

- **图片（Image）**：项目应始终包含图片或视觉元素。
- **标题（Title）**：轮播项目通常应包含标题，用于说明内容。
- **元数据（Metadata）**：使用元数据展示在当前回复上下文中与该项目最相关的重要信息。文本不要超过两行。
- **徽标（Badge）**：在合适的地方使用徽标来展示辅助性上下文信息。
- **操作（Actions）**：尽可能为每个项目提供单一且明确的 CTA。

**经验法则**

- 为保证可读性，**每个轮播的卡片数量应保持在 3–8 个**。
- 元数据只保留最相关的细节，最多不超过三行。
- 每张卡片可以有一个可选的 CTA（例如 “Book” 或 “Play”）。
- 在各卡片之间保持一致的视觉层级。

### 全屏（fullscreen）

超越内联卡片的沉浸式体验，为用户提供进行多步骤工作流或深入探索的空间。ChatGPT 的输入框（composer）仍悬浮于上层，让用户可以在全屏视图的上下文中通过自然对话继续“与应用交流”。

**适用场景**

- 无法浓缩为单张卡片的富交互任务（例如带图钉的交互式地图、功能丰富的编辑画布或交互式图表）。
- 浏览详细内容（例如房产房源信息、菜单）。

**布局**

![全屏模式示意图](https://developers.openai.com/images/apps-sdk/fullscreen_layout.png)

- **系统关闭按钮（System close）**：关闭面板或视图。
- **全屏视图（fullscreen view）**：内容区域。
- **输入框（Composer）**：ChatGPT 的原生输入框，允许用户在全屏视图的上下文中继续追问。

**交互**

![全屏模式交互模式示意](https://developers.openai.com/images/apps-sdk/fullscreen_interaction_a.png)

- **聊天面板（Chat sheet）**：在全屏界面旁边保留对话上下文。
- **思考中（Thinking）**：输入框呈现“微光流动”效果，表示回复正在流式生成。
- **回复（Response）**：当模型完成回复后，输入框上方会显示一个临时性的、经过截断的回复片段。轻点该片段即可打开聊天面板。

**经验法则**

- **让 UX 设计与系统输入框协同工作。**全屏模式下输入框始终存在，因此请确保你的体验能够支持通过对话式提示触发工具调用（tool call），并让用户感到自然。
- **将全屏模式用于需要更大空间的工作。**现有的编辑器和管理后台界面只要符合 [iframe 政策](https://developers.openai.com/plugins/plugin-guidelines#iframes-and-embedded-pages)，就可以嵌入使用。

### 画中画（Picture-in-picture，PiP）

ChatGPT 内的一个持久悬浮窗口，专为游戏或视频等持续性或实时会话优化。在对话继续进行时，PiP 窗口保持可见，并能根据用户提示动态更新。

**何时使用**

- **与对话并行进行的活动**，例如游戏、实时协作、测验或学习会话。
- **PiP widget（组件）能够响应聊天输入的场景**，例如根据用户请求继续游戏回合或刷新实时数据。

**交互**

![画中画的交互模式](https://developers.openai.com/images/apps-sdk/fullscreen_interaction.png)

- **激活时：**滚动页面时，PiP 窗口固定在显示区域顶部
- **固定时：**PiP 保持固定，直到用户将其关闭或会话结束。
- **会话结束时：**PiP 回到内联位置并随页面滚动离开。

**经验法则**

- **确保 PiP 状态能够更新或响应**用户通过系统输入框（composer）进行的交互。
- 会话结束时**自动关闭 PiP**。
- **不要在 PiP 中塞入过多控件或静态内容**，这类内容更适合内联或全屏模式。

## 视觉设计指南

一致的外观和体验有助于让合作伙伴构建的工具成为 ChatGPT 平台浑然一体的组成部分。视觉规范旨在保障清晰性、易用性和无障碍性，同时在合适的位置为品牌表达留出空间。

这些原则说明了如何运用颜色、字体、间距和图像，在保持系统清晰性的同时，为合作伙伴留出彰显自身服务特色的空间。

### 为什么这很重要

视觉与 UX 的一致性有助于提升在 ChatGPT 中使用应用的整体体验。遵循这些规范，合作伙伴能够以让用户感到一致的方式呈现自己的工具，在传递价值的同时不造成干扰。

### 颜色

系统定义的调色板有助于确保操作和响应始终与 ChatGPT 平台风格保持一致。合作伙伴可以通过强调色、图标或内联图像来体现品牌，但不应重新定义系统颜色。

![调色板](https://developers.openai.com/images/apps-sdk/color.png)

**经验法则**

- 文本、图标以及分隔线等空间元素使用系统颜色。
- 合作伙伴的品牌强调元素（如 logo 或图标）不应覆盖背景或文本颜色。
- 避免使用会破坏 ChatGPT 极简外观的自定义渐变或图案。
- 在应用展示模式内，主按钮上可使用品牌强调色。

![颜色使用示例](https://developers.openai.com/images/apps-sdk/color_usage_1.png)

_在强调元素和徽章上使用品牌色。不要更改文本颜色或其他核心组件样式。_

![颜色使用示例](https://developers.openai.com/images/apps-sdk/color_usage_2.png)

_不要在文本区域的背景上使用颜色。_

### 字体排版

ChatGPT 使用平台原生系统字体（iOS 上为 SF Pro，Android 上为无衬线字体），以确保在各类设备上的可读性和无障碍性。

![字体排版](https://developers.openai.com/images/apps-sdk/typography.png)

**经验法则**

- 始终继承系统字体栈（font stack），并遵循系统针对标题、正文和说明文字的字号规则。
- 粗体、斜体或高亮等合作伙伴样式仅用于内容区域，不用于结构性 UI。
- 尽量减少字号变化，优先使用 body 和 body-small 字号。

![字体排版示例](https://developers.openai.com/images/apps-sdk/typography_usage.png)

_不要使用自定义字体，即使是在全屏模式下。尽可能使用系统字体变量。_

### 间距与布局

一致的外边距、内边距和对齐方式，能让合作伙伴的内容在对话中易于浏览且行为可预期。

![间距与布局](https://developers.openai.com/images/apps-sdk/spacing.png)

**经验法则**

- 卡片、集合和检查器（inspector）面板使用系统网格间距。
- 保持内边距一致，避免内容拥挤或文字顶边贴边。
- 尽可能遵循系统指定的圆角大小，以保持形状一致。
- 通过标题、辅助文本和 CTA（行动号召）的清晰顺序来维持视觉层级。

### 图标与图像

系统图标体系提供视觉清晰度，而合作伙伴的 logo 和图像则帮助用户识别品牌背景。

![图标](https://developers.openai.com/images/apps-sdk/icons.png)

**经验法则**

- 使用系统图标，或符合 ChatGPT 视觉风格的定制图标——单色且描边风格。
- 不要将你的 logo 作为响应内容的一部分。在 widget 渲染之前，ChatGPT 总会自动附加你的 logo 和应用名称。
- 所有图像必须遵循强制规定的宽高比，以避免变形。

![图标与图像](https://developers.openai.com/images/apps-sdk/iconography.png)

### 无障碍

每一位合作伙伴打造的体验都应让尽可能广泛的用户群体可以使用。在为 ChatGPT 构建应用时，无障碍性（Accessibility）应作为核心考量。

**经验法则**

- 文本与背景必须保持最低对比度（WCAG AA）。
- 为所有图像提供替代文本（alt text）。
- 支持文本缩放而不破坏布局。
